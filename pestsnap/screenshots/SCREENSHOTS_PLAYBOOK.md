# PestSnap — конверсионные скриншоты, r1

Постоянная галерея: https://love8ko.github.io/pestsnap/screenshots/

Задача владельца: первые три App Store скриншота, от того, что нужно аудитории для скачивания. Продукт можно подтянуть. Формат — Cysta/Hepatica/Salvora: понятный двухстрочный заголовок, две строки пользы, узнаваемая сцена, крупное доказательство результата. Английский мастер, пояснения по-русски.

## Актуальная база

2026-09-22. Ветка `love8ko/screenshots` fast-forwarded из `love8ko/sprint`, последний продуктовый SHA `4db256909efb8a8921764e0a0ba5c4a241028925`. Прочитаны новые DECISIONS.md, код кейсов/записи/PDF, исследования аудитории и продления. V1-документы не задают новый продукт.

Последняя инструкция владельца важнее принципа «только уже готовые функции»: потребность и сильное обещание определяют концепт, разрывы с реализацией фиксируются отдельно. Никогда не выдаём концепт за готовый интерфейс, модельные предпочтения за реальную конверсию.

## Что готово

| ID | Заголовок | Польза | Причина позиции |
|---|---|---|---|
| P01 | What’s this bug? / Snap to find out. | Identify pests from a photo / Know what to do next | Широкая исходная потребность; сразу понятны объект и действие |
| P02 | How do I / get rid of pests? | Know what to do today / Know when to call a pro | Желание решить проблему, а не получить латинское имя |
| P03 | Droppings? Damage? / What left this? | Photograph the clues / Find the likely pest | Широкая потребность домовладельцев/арендаторов, когда жука нет |

Основной ряд рассчитан прежде всего на домовладельца. В отдельном варианте для арендаторов сильнее PDF-запись; r0 сохранён, его нельзя считать безусловно проигравшим.

## Когорты и порядок болей

Jev, 24 синтетических сценария из спринта: 8 homeowner, 5 renter, 4 parent, 4 petowner, 3 generic. Два прохода с обратным порядком. Это не 24 живых человека. Средние Score по шкале 0–4, не проценты установок.

- Домовладельцы: определить вредителя 3.60 → действия 2.70 → следы 2.03. Заголовки: «What’s this bug?», «How do I get rid of pests?», «Droppings? Damage?».
- Арендаторы: запись/письмо 2.57 → следы 2.31 → укусы 1.84. «Pests in your rental? / Send a clear record.»; «Woke up with bites? / Know where to look.».
- Родители: предупреждающие признаки/помощь 3.22 → возможное определение 2.43 → действия 1.89. «Worried about a bite? / Know when to get help.».
- Владельцы питомцев: клещ/блоха + действия 3.38 → определение 2.86 → действия 2.39. «Tick on your dog? / Know your next step.».
- Generic: определить 2.42; большинство остальных функций малоинтересны. Не оптимизируем основную подписную витрину под праздное любопытство.

Общий редакционный порядок на панели с проблемой (21 сценарий, generic исключены): ID 2.74 → action 2.17 → evidence 1.54 → family 1.21 → progress 1.18 → cost 1.14 → bites 0.86 → record 0.83 → pet 0.81. Состав панели не отражает доли трафика. Узкие темы в хвосте не «слабые»: они лидируют внутри своей когорты. Вопрос first_choice даёт другой акцент, сохранён отдельно; порядок выбран по широте релевантности + primary homeowner, а не выдан за объективный рынок.

## Проверки и итерации

1. Прочитаны примеры Salvora и Cysta, общий портфельный плейбук из Hepatica, материалы BumpCheck.
2. До актуализации спринта — предварительные шесть сценариев; их результаты не используются как основание финального ранжирования.
3. После синка спринта — r0: ID → план → PDF. Три фотографии, HTML/CSS, 1320×2868.
4. После уточнения владельца «от аудитории, продукт подтянем» — полноценное сравнение девяти задач у 24 сценариев, затем отдельное сравнение трёх заголовков в каждой из трёх задач.
5. r1: прямой вопрос об избавлении; предметные «Droppings? Damage?»; «it» заменено на «pests» для автономного понимания второго кадра. Это редакционные сокращения протестированных формулировок, а не дословные победители первого тура.
6. Фотографии P01/P03 исправлены: экран телефона к человеку, камера к объекту. Неправильные исходники сохранены с provenance, финал использует `-v2`.
7. Финальный текст всего ряда сравнен с r0 ещё у 24 сценариев × 2 порядка; Jev не видел пиксели.
8. Визуальная проверка 180/220 px и полноразмерного рендера; отдельная проверка responsive-галереи и lightbox.

## Воспроизведение

Node 24 + Google Chrome, Python 3; npm не нужен.

```sh
node marketing/appstore-v3/scripts/render.mjs
python3 marketing/appstore-v3/scripts/build-gallery.py
```

Рендер 440×956 CSS px × 3 = 1320×2868, PNG RGB без альфы. Шрифт Manrope локальный. Рендер не делает сетевых запросов. Проверить каждый headline/benefit на overflow, изображения на decode, высоту текстовой области и кадры в маленьком размере. Галерея должна показывать эти же байты; ZIP содержит ровно три мастер-PNG.

## Продукт и честность

V2 собрана и запущена в отдельном симуляторе; launch capture сохранён. Runtime-проверка всех scan/case/PDF/покупок в этой сессии не проводилась. Использованы также реальные снимки предыдущего спринта. Нижние карточки — редакционные визуализации, не неизменённые скриншоты сборки.

PDF уже подключён в My home. Генератор LandlordLetter существует, но не имеет UI-вызова в текущей базе. Для renter-концепта письмо допустимо как целевое обещание, но перед App Store оно требует реализации. Список задач отдельно в PRODUCT_GAPS.md.

Не использовать обещания: безопасность по фото, точный диагноз укуса, гарантированное уничтожение, 3 секунды без замера, проценты уверенности, фальшивые отзывы/врачи, юридическое доказательство, бесплатный скан/триал без соответствующей доступности. Не копировать опасные/устаревшие факты из V1-персон.

Сохранять эту страницу и slot IDs. Для конкретного трафика менять начало серии по когорте. Изменения заголовков не требуют новых фото.
