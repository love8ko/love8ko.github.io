Как это масштабировать на 100+ пользовательниц

26.09.2026, по живому тесту на Starter и официальным лимитам.

Замер

  • Создание мгновенного клона: 3,2 с. Озвучка 20–24 с текста: Multilingual v2 — 3,5–4,2 с, v3 — 9–10 с, Flash v2.5 — 1,2 с. Удаление — сразу.
  • После «создал → озвучил → удалил» счётчик voice_add_edit_counter = 1: удаление голоса не возвращает попытку.

Что это значит

  • Каждая новая версия трека после правки слов = новый клон (мы голос удаляем) = −1 из лимита. 100 платящих × 4 правки в месяц = 400 созданий + триалы → нужен Scale ($299) уже на сотне платящих.
  • Слоты (одновременно живых голосов) не проблема при схеме «создал → озвучил → удалил»: голос живёт ~5–15 с, очередь заданий на сервере.

Как уложиться

  1. Не удалять клон сразу, а держать его 24–72 часа после записи: все правки первой сессии/первых дней — без новых созданий. Удалять по таймеру. Слоты при этом нужны (Scale/Business — сотни).
  2. Правки пакетом: пользовательница правит несколько строк → одна новая версия.
  3. Лимит новых версий в подписке (например, 4 в месяц) — и по экономике, и по созданиям голосов.
  4. При росте — Enterprise (без лимита созданий) или второй провайдер (Cartesia: лимиты созданий не проверены).
  5. Хранить у себя её исходную запись с отдельным согласием (BIPA) — иначе для новой версии нужна новая запись.
