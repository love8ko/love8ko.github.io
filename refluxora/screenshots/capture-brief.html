Three screens.
Six finished compositions.

Replace the designed product examples with approved captures when the app is ready.

Capture requirements

  • English (US), approved production UI, portrait 1320 × 2868 preferred. Capture the entire screen at native resolution. No DEV overlays or keyboard obscuring results.
  • Use synthetic data. No real patient names, identifiers, reports or conversations.
  • Provide the image file, app build or commit, capture date, demonstration input and approval reference.
  • Capture in the development chat’s agreed window. This marketing workspace must not control the simulator or change app data.

01 · Coach

Required result: An answer to your question.

A substantive answer to “Why is my heartburn worse at night?”, with AI identification. Verify that any displayed source supports the answer and the native source link works. Show the answer, not only the question editor.

Current code references:

  • Refluxora/Refluxora/Core/Tabs/Coach/CoachThreadDetailView.swift
  • Refluxora/Refluxora/Services/CoachService.swift

02 · Lab results

Required result: A result, explained.

A confirmed laboratory field with value, units and laboratory reference, followed by the actual explanation. The review fixture uses B12 220 pg/mL and an illustrative 200–900 interval. These are synthetic data, not a universal normal range. Show the explanation, not only the Explain button.

Current code references:

  • Refluxora/Refluxora/Setup/LabReviewView.swift
  • Refluxora/Refluxora/Setup/LabObservation.swift

03 · Menu review

Required result: One dish. One practical change..

A specific menu item and an explainable adjustment before ordering. The review uses grilled salmon with lemon butter sauce and suggests asking for sauce on the side. Avoid generic safe-food labels, measured pH or a personal trigger claim.

Current code references:

  • Refluxora/Refluxora/Capture/MenuPreScan/MenuDishDetailSheet.swift
  • Refluxora/Refluxora/Capture/MenuPreScan/MenuPreScanResultView.swift

Release gate

Concept files are excluded from release export. Production PNG export requires an approved capture, a recorded approval reference and verified UI/claim correspondence for every frame. A and B use the same underlying result. If one result is unavailable, keep that frame pending and continue the others.
